# 매핑표 v0 실측 검증 보고 (리포트 PoC)

> - 실행일: 2026-09-11 · 엔진: axe-core 4.13.0 · 규칙 세트 baseline(+target-size)
> - 대상 ①: KRDS 공식 킷 데모 74파일 (v1.1.0, 커밋 d6bb184) — 킷 CSS/JS 하네스로 렌더
> - 대상 ②: https://www.krds.go.kr (킷 사용 확인 — `ui-script.js`·`krds-*` 클래스·`--krds-box-shadow-outline` 동일)
> - 목적: 매핑표 v0의 ①② 판정 검증과 `?` 41건 해소 (설계 문서)

## 1. 총평 — ① 반증 0건

**매핑표가 "킷이 보장한다(①)"고 판정한 항목에서 위반이 검출된 사례는 없다.** 킷 데모 74파일에서 검출된 위반 12건은 전부 매핑표가 ②(조건부) 또는 ③(범위 밖) 또는 `?`(미분류)로 분류해 둔 자리에서 나왔다. 적대적 검증(표본 21건 중 8건 강등)을 거친 뒤의 ① 판정이 실측에서도 유지된 것으로, v0의 보수적 판정 원칙이 작동했다는 근거다.

단, **이는 "① 항목이 KWCAG를 준수한다"는 뜻이 아니다.** 자동 검사가 커버하는 범위는 33항목 중 일부(full 1 / partial 19)이고, 그 안에서도 형식 요건만 본다. ①의 실질 검증은 전문가 심사·보조기술 실사용 평가의 몫이다.

## 2. 킷 패턴과 공식 사이트의 관계 — 확정된 것과 아닌 것

> **2026-09-11 정정.** 최초 작성 시 3건을 모두 "킷 결함의 사이트 전파"로 기술했으나, 노드별 판정과 사이트 DOM 수동 확인 결과 근거의 강도가 서로 달랐다. 아래가 정정된 판단이다.

| 사안 | 킷 데모 | krds.go.kr | 확정 수준 |
|---|---|---|---|
| `li[role=tab]` 내부 `<button>` 중첩 | `tab`·`help_panel`·`tutorial_panel` — `nested-interactive` **위반** | `#tabInfo01~03`이 동일 구조(`<li role="tab"><button>`) — **위반** | **킷 마크업 패턴 자체의 문제로 확정.** 사이트도 같은 구조를 쓴다 |
| 건너뛰기 링크 대상 | `skip-link` 위반이 나왔으나 **조각만 렌더한 하네스 탓이 크다** — 근거 약함 | `<a href="#breadcrumb-home">본문 바로가기</a>`이고 해당 id가 **페이지에 없음**(수동 확인) — **위반** | **사이트 결함은 확정.** 킷 쪽은 "샘플 기본값이 본문이 아닌 브레드크럼을 가리킨다"는 위험한 기본값 문제이지 코드 결함은 아니다 |
| `aria-controls` 유효성 | `header`·`side_navigation` — **판정 보류** | **판정 보류** (위반 아님). axe 메시지: "aria-haspopup 사용 시 대상 id 존재 여부를 판단할 수 없음". 수동 확인 결과 대상 id는 **실재했다** | **위반 아님.** 최초 기술은 오류였다 |

정정 후에도 유지되는 결론은 다음과 같다:

- **킷 마크업 패턴의 문제가 사이트에 그대로 나타난다** — 탭 중첩 1건이 킷 소스와 사이트 DOM 양쪽에서 동일 구조로 확인됐다. 부품 수준에서 교정하는 접근(1층 MCP)의 근거로 충분하다
- **탭 중첩 건은 KRDS 운영팀이 이미 수용했다** — 동일 지적에 대해 "부적절함을 확인", "`role="tab"`을 초점 요소에 직접 부여하도록 수정하겠다"는 회신이 있다. 우리 분석이 킷 소스만 읽고 같은 결론에 도달했다는 점에서 판정 방식의 타당성을 뒷받침하지만, **동시에 이 판정이 킷 버전에 종속됨을 뜻한다** — 개정 시 재검증 대상이다 (설계 문서의 버전 추적 필요성)
- **킷을 쓴다고 접근성이 보장되지는 않는다** — 공식 킷을 사용한 공식 사이트에서 자동 검사로 위반이 검출된다(건너뛰기 링크 대상 부재, 탭 중첩, 명도 대비)
- **위험한 샘플 기본값은 실제로 복사된다** — 킷 샘플의 `#breadcrumb` 계열 대상이 사이트에서 `#breadcrumb-home`(존재하지 않음)으로 나타난다. 매핑표가 이를 ②(skipTargetId 필수)로 강제한 판단이 타당했다

### 건너뛰기 링크 결함 — 실사용 재현 증거

krds.go.kr에서 키보드로 직접 조작해 확인했다 (`evidence/` 스크린샷 3장):

| 단계 | 결과 |
|---|---|
| 평소 화면 | 링크가 보이지 않는다 — 킷 CSS가 `:not(:focus)`일 때 숨긴다 |
| Tab 1회 | 최상단에 "본문 바로가기"가 나타난다 (첫 초점 요소) — [evidence/skip-link-2-focused.jpg](evidence/skip-link-2-focused.jpg) |
| Enter | **초점이 링크에 그대로 남는다.** 해시만 `#breadcrumb-home`으로 바뀌고 스크롤은 0 — [evidence/skip-link-3-after-enter.jpg](evidence/skip-link-3-after-enter.jpg) |

자동 검사의 `skip-link` 위반("No skip link target")이 실사용 경험과 일치함을 확인한 사례다 — 번역표의 6.4.1 매핑이 실제 장애 상황을 가리킨다는 근거다.

### 6.4.1 수동 확인 절차 (실측으로 도출)

건너뛰기 링크는 "존재하는가"까지만 자동 판정되고 "작동하는가"는 수동이다. 세 가지 구현을 만들어 초점 이동을 측정한 결과, **판별 기준은 Enter 다음의 Tab이 어디로 가느냐**였다:

| 구현 | Enter 직후 초점 | 그다음 Tab | 판정 |
|---|---|---|---|
| 대상 id 없음 (krds.go.kr 현재 상태) | 링크에 그대로 | **메뉴 첫 항목** | 실패 — 건너뛴 것이 아니다 |
| 대상 있음 · `tabindex` 없음 | `BODY` | 본문 링크 | 동작하나 초점 위치가 불명확 |
| 대상 있음 · `tabindex="-1"` | 대상 요소 | 본문 링크 | 정상 |

**확인 절차**: 홈에서 Tab 1회 → 건너뛰기 링크 노출 확인 → Enter → **한 번 더 Tab** → 초점이 본문 내부 요소에 있으면 통과, 메뉴로 돌아가면 실패.

Enter 직후 스크롤이 움직이는 것만 보고 통과로 판정하면 안 된다 — 스크롤은 이동했는데 초점은 남아 있는 경우가 실재한다.

**방법론 교훈**: 자동 검사의 `incomplete`(판정 보류)를 위반으로 읽지 않는다. 이 보고의 최초 오류가 정확히 그것이었다 — 집계 단계에서 violation과 incomplete를 같은 evidence 배열에 담다 보니 요약에서 뭉뚱그려졌다. 판정 보류는 **사람이 확인해야 할 대상**이지 결함의 증거가 아니다.

## 4. ② 근거 실증 — 필수 입력 강제가 검사로 뒷받침되는가

매핑표가 ②(조건부·필수 입력)로 강제한 항목 중, 킷 기본 마크업 상태에서 실제로 위반이 검출된 사례:

| 컴포넌트 | ② 필수 입력 | 실측 |
|---|---|---|
| tts#icon | accessibleName | `button-name` 위반 — 아이콘 전용 버튼에 접근 가능한 이름 없음 |
| structured_list#table | rowCheckboxLabel | `label` 위반 — 행 체크박스 레이블이 빈 요소 |

두 건 모두 **매핑표가 예측한 바로 그 지점에서 검출**됐다. ②의 강제가 공허한 요구가 아니라 검사로 확인되는 요건임을 보여준다.

나머지 ② 항목(대체 텍스트 내용, 레이블 문구의 적절성 등)은 값을 비워도 axe가 검출하지 못하는 "내용" 영역이라, 검사가 아니라 **생성 시점 강제(1층 MCP)로만 담보 가능**하다. 이것이 "적용이 주축, 검사는 안전망"의 실증적 근거다.

## 5. 새로 발견된 킷 이슈 (매핑표에 없던 것)

| 컴포넌트 | 규칙 | 내용 |
|---|---|---|
| badge, badge#size | `color-contrast` | 킷 기본 토큰 조합에서 명도 대비 미달 |
| pagination | `color-contrast` | 동일 |
| structured_list#table | `empty-table-header` | 빈 표 헤더 셀 |

명도 대비는 매핑표가 ③(렌더 후 axe 실측 위임)으로 둔 항목이다. **검사층이 실제로 이를 잡아냈으므로 3층 구조가 설계대로 작동한 것**이지만, 동시에 킷 토큰을 그대로 써도 대비가 미달하는 조합이 있다는 뜻이라 킷 이슈 목록에 추가한다.

판정 보류(`color-contrast` incomplete)가 킷 12파일·사이트 16노드에서 나온 것도 기록해 둔다 — 그라데이션·이미지 배경 등으로 기계 판정이 불가능한 경우이며, 전부 수동 확인 대상이다.

## 6. ③ 검증 — 페이지 수준 항목이 실제로 검출되는가

krds.go.kr 검사에서 페이지 수준 항목이 정상 검출됐다:

- **6.4.1 반복 영역 건너뛰기** — `skip-link`·`landmark-one-main`·`region` 위반 (15노드)
- **6.4.2 제목 제공** — `heading-order` 위반 (`.banner > h3` — 제목 위계 건너뜀)
- **6.1.3 조작 가능** — `target-size` 위반 1건 (옵트인 규칙을 활성화했기에 검출된 것)

매핑표가 컴포넌트 단위로 판정 불가라며 ③으로 위임한 항목들이 조립된 페이지에서 검출됐다 — **③ 위임 판단이 옳았음을 확인**한 것이다.

## 7. 방법론상 확정 사항

1. **킷 데모는 마크업 조각이라 하네스가 필요하다** — 킷 CSS/JS를 입힌 문서로 감싸 렌더한다. `setContent`는 `about:blank` 오리진이라 `file://` 리소스가 차단되므로 임시 파일로 쓴 뒤 연다
2. **kit-demo 모드에서는 페이지 수준 규칙을 끈다** — 하네스가 만든 `landmark-one-main`·`page-has-heading-one`·`document-title`·`html-has-lang` 위반은 하네스 산물이지 컴포넌트 판정이 아니다. 이 항목들은 site 검사가 담당한다
3. **`target-size`는 기본 비활성이므로 명시 활성화가 필수다** — 켜지 않으면 6.1.3이 조용히 미검사로 남는다

## 8. 남은 `?` — 자동 검사로 해소 불가

`?` 41건 중 위 10건이 해소됐다. 나머지는 다음 이유로 자동 검사 범위 밖이라 **스크린리더 실사용·수동 조작 확인이 필요**하다:

- 초점 관리 동작 (modal의 Escape·inert 배치, contextual_help의 초점 복귀, calendar 그리드 화살표)
- 자동 검사가 "없음"으로 판정하지 못하는 것 (aria-modal 미설정, 캐러셀의 초점 유지)
- 페이지 조립 맥락에 달린 것 (제목 수준 조정, 도움 정보 일관성)

**자동 미검출을 ① 승격 근거로 쓰지 않는다** — axe가 잡지 않았다는 것은 "위반이 없다"가 아니라 "그 규칙으로는 판정하지 못했다"이기 때문이다.
